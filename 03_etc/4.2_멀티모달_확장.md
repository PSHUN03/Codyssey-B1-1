## 2. 도식 구성 — 설계 문서와의 대응

이미지는 좌 → 중 → 우의 **입력 → 처리 → 산출** 흐름과, 그 아래 **검증·개선 루프**로 구성된다. 각 블록은 설계 문서의 절과 1:1로 대응한다.

| 도식 블록 | 표시된 내용 | 대응 절 |
|---|---|---|
| **사용자 및 입력 데이터** | 타겟: 대학생, 연구 초심자 / ① 요구 조건(3단 구조·계층 목록·분량·톤) ② 다관점 원문(철학·심리학 자료) | [§2.1.1](../01_document/2_시스템_설계_문서.md#211-타겟-사용자-누가-쓰는가) · [§2.1.2](../01_document/2_시스템_설계_문서.md#212-입력-데이터-형태-어떤-정보를-받는가) |
| **개요 설계자 — 시스템 프롬프트** | 페르소나·규칙·우선순위 / 규칙 4항: 원문 충실성 · 논리적 구조 완결성 · 형식 규격 준수 · 표현의 간결·명료함 | [§2.3](../01_document/2_시스템_설계_문서.md#23-페르소나-정의) · [§2.4](../01_document/2_시스템_설계_문서.md#24-시스템-프롬프트-설계) |
| **Few-shot 예시** | 예시 1–2(좋은 입력/출력) · 예시 3(AI 되묻기) | [§2.5](../01_document/2_시스템_설계_문서.md#25-few-shot-예시-최소-3개) |
| **계층형 개요 (산출 목표)** | 1. 서론 / 2. 본론(소주제 3개 이상, 각 논지 1~2문장) / 3. 결론 / `1. → 1-1. → 1-1-1.` / [추가 논점] 2가지 제안 | [§2.1.3](../01_document/2_시스템_설계_문서.md#213-출력-규격-어떤-형식으로-내는가) |
| **환각 검증 및 개선 프로세스** | 환각 정의(사실 왜곡·출처 날조·과잉 단정) / 사실 기반 검증 질문 Q1~Q7 / 판정 기준 Pass(A: 우수, B: 양호) · Fail(F1 단정 오류, F2 출처 날조, F3 임의 답변) | [§2.7](../01_document/2_시스템_설계_문서.md#27-환각hallucination-검증-설계) |
| **개선 이력 (v1 → v2)** | 검증 결과가 프롬프트 개선으로 되돌아오는 피드백 루프 | [§2.8](../01_document/2_시스템_설계_문서.md#28-개선-이력-환각-검증-설계-v1--v2) |

> **도식이 보여주는 핵심** — 설계가 **단방향 파이프라인이 아니라 루프**라는 점이다. 산출된 개요는 환각 검증(Q1~Q7)을 거치고, 그 판정 결과가 `개선 이력(v1 → v2)`을 통해 시스템 프롬프트로 되돌아간다. 이는 [§2.8](../01_document/2_시스템_설계_문서.md#28-개선-이력-환각-검증-설계-v1--v2)의 개선 과정과 [3.1.6 성공 판정 기준](../01_document/3_실행_로그.md#316-성공-판정-기준)의 피드백 루프를 그림 한 장으로 압축한 것이다.

## 3. 판독 시 유의 사항 (이미지 생성 AI의 한계)

시각 자료 자체도 생성 AI의 산출물이므로, 텍스트 산출물과 동일한 기준으로 검토했다. 아래는 **이미지에 남은 렌더링 오류**이며, 설계 내용의 오류가 아니다.

| 위치 | 이미지 표기 | 정확한 표기 | 원인 |
|---|---|---|---|
| 검증 질문 인물 아이콘 | 사스토틸 | 아리스토텔레스 | 한글 글자 조합 렌더링 오류 |
| 검증 질문 인물 아이콘 | 현대 성리 | 현대 심리 | 한글 글자 조합 렌더링 오류 |
| '개요 설계자' 박스 아이콘 | 타 서비스 로고 형태 | Claude Opus 4.8 | 학습 데이터 편향에 따른 아이콘 오생성 |

> **시사점** — [§2.7.1](../01_document/2_시스템_설계_문서.md#271-환각의-정의)이 정의한 **① 사실 왜곡형** 환각이 텍스트가 아닌 **이미지 레이어에서도 동일하게 발생**한다는 사례다. 따라서 시각 자료 역시 산출 후 라벨 대조 검수가 필요하며, 도식의 구조(블록·화살표·흐름)는 유효하나 **라벨 텍스트는 위 표로 보정해 읽어야 한다.**
